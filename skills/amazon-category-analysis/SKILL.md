# 亚马逊类目分析

通用Agent Skills技能。定位本技能根目录，以相对路径读取资源，使用当前agent的浏览、文件与计算能力；agents/openai.yaml是可选UI元数据。无需安装其他技能即可完成本技能；可衔接选品或利润分析。

## 范围与工具

沿用站点、细分类目节点／核心关键词、配送地区、采集日和统计周期。执行市场容量、类目竞争或两者；用户泛称“分析这个类目”时默认两者。范围未知先向用户确认；已有关键词可先定义细分需求市场，标明它与BSR类目的边界。

Jungle Scout有用户提供的可用key时执行Keyword Scout／Keywords by ASIN反查；未提供key时直接跳过该工具并记录原因，不要求用户补key才能继续。用户已提供的导出仍可读取，注明“读取提供数据”，不声称执行了反查。凭据只通过当前agent的安全渠道使用，不写入报告、仓库或日志。

Sorftime有可用key时优先做BSR类目分析；无key时直接降级Flapen＋ASINSIGHT及Amazon公开页面。各工具按实际权限和站点覆盖使用；缺工具不代表没有市场需求或竞争较小。

## 执行

1. 固定研究范围及周期，建立工具状态表（已使用／读取提供数据／未提供key跳过／无权限／未覆盖）。模板或技能配置请求只创建规则与空表，不采集或追问真实商品成本。
2. 分析市场容量时读取[market-capacity.md](references/market-capacity.md)。反查代表ASIN的关键词，核对搜索量及搜索排名；统计完整Top100可得销量，查看代表产品与目标排名销量。分别给出工具估算和经验情景，保留原始来源及缺口。
3. 分析类目竞争时读取[category-competition.md](references/category-competition.md)。执行Top100新品、评论、垄断、卖家类型、内容及星级分析，或Top50低评论卖家分析；两条都可得时交叉核验。保持样本与分母独立。
4. 按[output-contract.md](references/output-contract.md)输出容量与竞争结论表、关键词与榜单证据、工具状态及下一步。容量只描述需求与可争取的销量范围，竞争信号只描述门槛；二者不能单独断言商品可做。
5. 衔接选品时写入现有选品工作簿的“市场与关键词”“竞争分析”“类目判断”，保留用户数据和公式。最终可做结论仍需自有方案利润、关键词广告承受力和差异化验证；进入完整利润测算，必要输入缺失必须向用户追问。

## 完成条件

所请求的每个分析部分均有结论或具体缺项，数字注明单位、周期、站点、统计定义、来源、采集日与数据状态。缺Jungle Scout key属于跳过路径，不阻塞其他分析；不足Top100／Top50不冒充完整样本。搜索排名不直接变成搜索量，搜索量不直接变成销量，经验倍数不当作实测。仅完成类目研究时，最终建议使用“继续研究／待验证／暂缓”，不替代利润否决。
