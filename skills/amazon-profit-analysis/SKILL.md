# 亚马逊利润分析

以一个站点、一个销售单位、一个币种和明确广告分母为计算单元。先核验必要输入，再计算；阻塞计算的条件缺失时必须要求用户补充，不能靠默认成本或行业均值填平。

## 输入关卡

读取 [input-contract.md](references/input-contract.md)，从本会话、用户文件及可核验报价中提取已有数据，只问实际缺项。用户已给出且仍适用的参数沿用，避免重复询问。

- 必要条件包括站点、销售币种、FBA/FBM、销售单位、优惠后售价及含税口径、各项单件必要成本、广告计算模式及该模式的参数，以及成本范围确认。
- 跨币种转换需要方向明确、有日期及来源的汇率；整票运费或月度费用需要匹配的分摊依据。直接采用已明确的单件金额时不再索取无关分摊数据。
- 数值0只有在明确无该费用或已包含于其他已知成本时可用，并记录依据及归属。空白、null、未提供都表示缺失，不能转换为0。
- 若必要费用不能从当前资料或已授权工具得到，向用户列出字段、单位、所需口径及缺失影响，允许一次批量回答或提供报价单。能获得明确费用金额时，不必让用户再输入推导费用所需的尺寸、重量。
- 使用可用的用户输入工具发问；没有该工具时在回复中明确要求补充。必需回答尚未到达时保持问题待答，只继续整理已有来源与不依赖缺项的工作。等待时间不构成回答。

缺项时输出“待补输入”与实际缺项清单，不输出完整净利或达标结论，也不能以一份长期待验证报告结束这次利润请求。若用户无法提供，记录尚未完成及原因；可以整理明确标为局部的已知成本，但不能推断完整利润。

## 计算

读取 [profit-model.md](references/profit-model.md)。用 [input-template.json](assets/input-template.json)组织数据并运行：

```bash
node scripts/calculate_profit.mjs --input /path/to/input.json --output /path/to/profit-result.json
```

脚本仅依赖Node内置库。返回码2及status=needs_input意味着必须向用户询问missing/invalid列出的必要条件；补齐后重跑。返回码1为文件或调用错误，先修复错误。必要输入完整才返回数值结果。

沿用既定用户门槛：目标ACoS30%，毛利安全余量5个百分点，即最低毛利率35%，35%包含边界；两项可调整。若当前测算ACoS高于目标，以较高者加安全余量作为门槛。ACoS模式按广告归因销售额计算；整体订单模式用TACoS或ACoS乘广告归因销售额占比，不能用订单占比代替销售额占比。

毛利率低于门槛或完整成本下单件净利≤0，利润一票否决；输入中含估算或情景时，明确为情景结果，不宣称实际盈利。即使利润达标，也只说明通过利润关卡，不能替代市场与竞争判断。

需要情景比较时分别补齐每个情景的依赖，改变售价后重新核实佣金及适用履约费用，不能把旧价格的固定费用外推为准确报价。月度利润需另取得销售件数和匹配的月度成本分摊；基础单件测算不强求销量。不要计算未经请求、缺少依据的现金流、税额或库存回报率。

## 输出与交接

默认输出简洁利润表：产品/站点/销售单位/币种/广告口径、售价、各项成本、毛利润与毛利率、广告成本及广告后利润、完整成本单件净利及净利率、最低毛利率、盈亏平衡广告率、采购上限约束、否决或利润门槛达标结论、来源与估算限制。含成本口径的单件净利不能称为公司会计净利润。

用户要求Excel或更新选品表时使用可用的 spreadsheets 技能，将输入、来源和可编辑参数与公式结果一并保存。保持选品表“评分”是商品星级；利润结果写入对应采购/头程/佣金/履约/包装其他/仓储/税费/退货/毛利/净利列。运营分摊须新增独立列并让净利公式扣除，保持原毛利定义；已有费用归属相同项时避免重复扣除。广告整体口径结果不可写进仍按售价×ACoS计算的旧公式：同步修改公式和口径说明，或单独列出整体订单情景。

配合 $amazon-product-direction 使用时，初筛阶段可以保留待验证利润；一旦用户进入本利润分析阶段，缺失必要条件就执行本skill的追问关卡。以必要输入补齐、重算成功、结论可追溯为完成条件。
